## Blockers and fixes

- B1 (fetch `success` with `http_status=0` accepted): the fetch branch of
  `RecordAttempt` now rejects `success` unless `HTTPStatus == 200`
  (`invalid_evidence`, "fetch success requires http status 200"). Status 0
  with `success` remains reachable only through `RecordReceipt` for
  `host_local` receipts, per the origin carve-out. Covered by
  `TestRecordAttemptFetchSuccessRequires200`.
- B2 (receipt bytes stored undecoded): `RecordReceipt` now strict-decodes the
  bytes against the closed receipt document grammar (members exactly
  `receipt_id`, `request_id`, `offer_id`, `task`, `outcome`,
  `validator_version` and a seven-member `usage` array of
  `{component,known,value}`), rejects unknown members (prompts, images, file
  contents, tool outputs, credentials fail mechanically), rejects duplicate
  or missing usage components, and cross-checks the document against the
  submitted `RecordReceiptParams` (receipt/request/offer IDs, task, outcome,
  component set, known flags, values). Grammar pinned in delivery-storage.md
  V4. Covered by `TestRecordReceiptRejectsForbiddenPayload`.
- B3 (no signed 53-bit integer boundary): `checkNumberBounds` walks decoded
  documents with `json.Number` and rejects integers outside
  [-(2^53-1), 2^53-1] at both the `canonicalize` and `strictDecode`
  boundaries; receipt usage values are checked directly. Hashes now pin
  exact facts. Covered by `TestCanonicalIntegerBounds`.

## Notes and fixes

- N1: `DeferJob` on a completed job is `conflict`; `CompleteJob` under a
  different fencing token is `conflict` (`TestDeferAndCompleteTerminalGuards`).
- N2: replay of `CompleteJob`/`DeferJob` returns the stored result without
  re-emitting the event; emission is gated on the completion/deferral row
  insert (`ct.RowsAffected() > 0`).
- N3: outbox aggregate sequences are minted under
  `pg_advisory_xact_lock(hashtext(aggregate_id))`.
- N4: observation CHECK (23514) rejections in the fetch branch classify as
  `invalid_evidence` via `errors.As(err, &pgErr)`.
- N5 (stage_outputs concurrent duplicate race): declined. The jobs-row
  `FOR UPDATE` taken at `RecordAttempt` entry serializes writers per job, so
  the pre-check race requires two writers on one job row, which the lock
  prevents; untestable defensive code rejected.
- N6/N8: the projection policy grammar requires `weights`, `task_map` and
  `zero_image_charge_evidence` present (`ZeroImageChargeEvidence *bool`);
  `RegisterProjectionPolicy` returns the stored row
  (`ProjectionPolicyState{Version, ContentHash, RecordedAt}`) on both first
  registration and identical replay.
- N7: `enqueue_job`/`recover_job` `not_found` for unknown source/lease
  recorded in delivery-storage.md V4 as an extension of the contracts
  taxonomy; `complete_job` returning the job ID as completion ID and
  `recover_job` returning derived state only (no reconciliation-fact table
  in this delivery) recorded there too.
- N9: `insertAssertion` carries `ON CONFLICT (observation_id,
  subject_source_id, subject_upstream_id, locator, payload_fingerprint) DO
  NOTHING`; a cross-job duplicate releases the savepoint and counts as

- N10: `offer_id` validation against the routing decision is deferred to the
  decisions store slice; recorded in delivery-storage.md V4 deltas.
- N11: tests added for B1/B2/B3, N1/N2; `mismatch[10]='x'` arm tightened
