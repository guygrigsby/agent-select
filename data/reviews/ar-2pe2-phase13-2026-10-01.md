## Blockers

1. **Crash between `publish_snapshot` and `retire_snapshot` permanently orphans the predecessor's retirement; the redelivery resolves as a freshness confirmation instead of completing the pipeline.**
   `internal/collector/successor.go:243-268` (`AttemptSuccessor`) derives everything from `latestPublication` at attempt time. Sequence: attempt publishes P2 and crashes before `RetireSnapshot` commits; no receipts were recorded, so the batch redelivers; the redelivery now sees P2 as `prev`, recompiles at a new attempt instant, finds masked-unchanged content (`contentEqual`) and returns `SuccessorConfirmed` — `P1` is never retired. Nothing else ever retires it: the next changed generation retires P2, not P1. `snapshot_retirements` and the `SnapshotRetired` event are silently lost forever, contradicting the at-least-once contract ("records no receipts, so the batch redelivers" implies the redelivery completes the work) and the normative step "retires the predecessor via `retire_snapshot` naming the successor hash and the new publication ID".
   Live-probed (`TestProbeP13RetirementLostOnRedelivery`, since removed): after a manual publish-without-retire, the redelivery returned `confirmed` and `snapshot_retirements` held 0 rows for gen1's hash. Fix shape: on the unchanged/confirmed path (and at reconciliation), retire any older publication on the channel that has no retirement row, naming the latest publication — or carry a durable per-batch pipeline mark so a redelivery resumes rather than re-derives.

2. **Double-hash class: event payload digest fields and the artifact locator carry `hex(sha256(artifact_hash))`, not `hex(artifact_hash)` — and Phase 13's store names files with the true hex, so `artifact_locator` resolves to no store path.**
   `hexHash(b)` is `hex(sha256(b))` (`internal/collector/canonical.go:84`). Applying it to an already-computed 32-byte digest re-hashes it. New code in this commit:
   - `internal/collector/successor.go:83-85` — `RetireSnapshot` payload `"artifact_hash": hexHash(artifactHash)` and `"successor_hash": hexHash(successorHash)`: both carry hash-of-hash, matching no row in `snapshots`/`snapshot_publications`.
   - `internal/collector/successor.go:73` — the error message prints `hexHash(successorHash)` as the successor hash: wrong value shown to callers.
   Meanwhile `ReconcileStore`/`store.go` name files `hexDigest(pub.ArtifactHash)` (correct, spec: `<root>/snapshots/<hex(artifact_hash)>.bin`), so the DB's `artifact_locator` (`snapshot://<hexHash>` — pre-existing `artifactLocator` in `snapshot.go:332`, same defect in `SnapshotCompiled`/`SnapshotValidated`/`SnapshotPublished` payloads) points at a hash that matches no file. Any consumer resolving the locator to the Phase 13 store gets a miss.
   Live-probed: all 5 `artifact_hash` payload fields across the three snapshot event names matched **no** real snapshot hash; the payload dump shows `artifact_hash` identical to the `snapshot://` locator suffix while store files sit at the true hex. This is systemic (the emitter-side instances predate this commit and passed earlier rounds), but this commit both extends it (`RetireSnapshot`) and builds the first locator-consuming layer on the correct convention, making the divergence functional. Fix sweep: use `hexDigest` for every already-computed digest (payload fields, locator, error message), including the pre-existing emitters, and pin it with a test that decodes `SnapshotPublished`'s payload against `snapshot_publications.artifact_hash`.

## Non-blocking notes

- **Spec sentence "No snapshot row, no publication" is not honored on the unchanged path.** Every attempt compiles at a new attempt instant, so each unchanged batch inserts a full `snapshots` row (artifact bytes included). Probed: `snapshots` rows 1 → 2 across one unchanged attempt. Either implement (pre-check is impossible without compiling, so this means a spec amendment or masking-before-persist) or amend the sentence to "no new publication"; the append-only table grows one full row per trigger batch either way.
- **"the rejection findings are logged" is unimplemented.** `successor.go:284-286` returns `SuccessorBlocked` and discards `validation.Findings`; the package has no logging at all.
- **Semantic-block and debounce paths are untested.** No test drives validation-rejected → receipts recorded with the prior generation intact, nor publish `forbidden`/`conflict`/`source_blocked` → blocked; nothing asserts one batch of N triggers yields exactly one attempt (the debounce is real in `RunSuccessorLoop` — `attempt` flag, one `AttemptSuccessor` per batch — but unproven).
- **No concurrent-publisher guard.** Two processes running the `publisher` consumer both scan the same undelivered batch (no claim/lease in `DeliveryScan`), compile distinct snapshots (different attempt instants) and both publish — messy but converging (newest-published wins). Spec says one loop per channel; safe only under that deployment assumption.
- **A malformed `CURRENT` file bricks the loop instead of healing.** `store.go:139-141` returns a storage error; startup reconciliation then fails and `RunCollectorWith` exits. The spec pitches the store as derived and rebuildable; reading `CURRENT` could fall back to re-adoption instead.
- **Persistent config-error hot-retry, silently.** `AttemptSuccessor` maps "no projection policy: bootstrap configuration is required" (`CodeInvalidRequest`, permanent) to the same no-receipts + 5s-retry path as transient storage errors, with no log; a misconfigured daemon retries forever with no signal.
- **In-process store staleness window.** If publish succeeds and `ReconcileStore` fails transiently, the in-process redelivery confirms freshness without reconciling; the store stays one generation behind until the next changed publication or restart (startup reconciliation heals it). The retirement blocker's fix should cover this too.
- **`RetireSnapshot` idempotent replay does not compare the stored `successor_hash`** — a replay with the same `(artifact_hash, publication_id)` but a different successor returns nil (`successor.go:57-63`). Unreachable from the pipeline; tighten while fixing blocker 2.
- **Dead code and a misleading follow-up commit.** `Ports.materialize` (`successor.go:356-360`) is uncalled; `4c2ac7e` is titled "drop dead materialize wrapper from successor pipeline" but only touches `.beads/issues.jsonl` — the wrapper is still there.
- **Spec-internal tension:** the V8 lead sentence says the loop runs "when the configuration carries a channel" while the field list makes `snapshot_validator_version` required; the implementation gates on the validator version (`daemon.go:103`). Field list is the sensible reading; consider fixing the lead sentence.
- Config defaults (`daemon.go:104-129`) match the spec names/defaults exactly (`snapshot_channel` local, `snapshot_distribution` local, `store_keep_generations` 2, `<UserConfigDir>/agent-routing/store`); no unit test covers `SuccessorConfigFrom`, but the mapping is trivial. Explicit `store_keep_generations = 1` fails at store construction (floor 2) — fail-fast, fine.

## Verified claims

- **Migration 0010 vs spec DDL:** column-for-column identical (`artifact_hash BYTEA FK snapshots`, `channel TEXT FK publication_channels(channel)`, `confirmed_at TIMESTAMPTZ`, PK `(artifact_hash,channel,confirmed_at)`, index `(channel,confirmed_at DESC)`); FK targets exist (0007 PKs); sequential numbering enforced by `migrate.go`.
- **`confirm_snapshot_freshness`:** appends with DB-time `now()`, no event, idempotent by PK via `ON CONFLICT DO NOTHING` — matches the spec sentence including "stamped at the port's transaction time".
- **`retire_snapshot` port:** validates successor publication pairing, rejects self-retirement, idempotent by `(artifact_hash, publication_id)`, emits `SnapshotRetired` (payload defect noted above). Matches contracts.md semantics (successor publication required, CHECK hashes differ also enforced in code).
- **Trigger vocabulary and debounce:** `eligibleTrigger` strict-decodes the exact 7-member `ObservationRecorded` payload (verified against the emitter in `ports.go:709-719`) and requires `outcome = 'success'`; non-trigger events are receipted without action; one batch → one attempt; receipts land only after resolution; shutdown mid-batch leaves events unreceipted for redelivery; storage failure backs off `PollIdle` rather than hot-spinning.
- **Input selection:** per-source latest success by `retrieved_at DESC, id DESC` (deterministic), governing policy admitted on research+extraction (+redistribution for distributable), policy pinned as `hexHash(config_hash)` — the exact convention `CompileSnapshot` re-verified inside its own rights gate, so eligible and contributing sets agree at the same instant.
- **Parameter inheritance / bootstrap:** distribution and projection policy inherited from the channel's latest publication; bootstrap falls back to daemon config and errors when no policy is pinned; compile instants are ms-aligned per `CompileSnapshot`'s contract.
- **Epoch-mask content equality:** `contentEqual` decodes both artifacts, masks `created_at`/`knowledge_cutoff` to the Unix epoch on deep copies (`Data()` copies), re-encodes canonically and byte-compares. `TestAttemptSuccessorUnchangedConfirmsFreshness` genuinely proves the mask (artifacts differ only in those two members and still confirm), freshness row appended, no publication, pointer unmoved.
- **Revocation semantics:** revocation excludes the source (live test asserts an empty-projection successor), the prior generation file stays readable, and `PublishSnapshot`'s in-transaction gate still refuses artifacts pinning a revoked source.
- **Store mechanics:** Stage is temp+fsync+rename+dir-fsync with hash-pins-bytes verification and identical-bytes no-op; corrupt existing file is restaged (repaired); Adopt re-verifies the pin (conflict on mismatch) and atomically swaps `CURRENT`; `CURRENT` holds exactly hex+newline; Prune keeps current + keep-1 newest by mtime, never touches CURRENT-named or DB rows; retention floor enforced at construction.
- **Reconciliation:** newest-by-`published_at`, ties by publication id (matches the spec rule); rebuilds missing file and corrupt bytes from `snapshot_bytes` (live-probed by the committed test), adopts when `CURRENT` disagrees, runs pre-first-scan and post-publish.
- **Loop end-to-end:** `TestRunSuccessorLoopPublishesOnEvent` proves event-driven publication with no manual kickoff and full receipt drain — the honest core of the exit criterion, though the trigger event is hand-seeded (shape verified identical to `record_attempt`'s emission) rather than produced by a real fetch.
