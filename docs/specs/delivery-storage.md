## Canonical byte encoding

Payloads, snapshots and typed stage outputs use one versioned canonical encoding, `canonical-v1`:

- RFC 8785 (JCS) JSON serialization: UTF-8, keys sorted by UTF-16 code unit, no insignificant whitespace, strings escaped per JCS. Implementations use the Apache-2.0 `github.com/cyberphone/json-canonicalization/go/src/webpki.org/jsoncanonicalizer` dependency, the same library [educated routing](educated-routing.md) pins; a from-scratch or stdlib `encoding/json` serializer is not permitted (stdlib escapes U+2028/U+2029 unconditionally and HTML characters by default, deviating from JCS), and independent fixtures are generated under the JCS rule.
- Field values are UTF-8 strings, boolean literals or integers in the signed 53-bit range (absolute value at most 2^53-1) only. No floating point, no null, no empty object placeholders. Optional facts are expressed by omitting the member, never by null. The 53-bit bound exists because JCS number serialization follows ECMAScript IEEE 754 rules; restricted to integers of this range, the JCS number algorithm reduces to plain decimal digits, so a serializer needs no floating point code and a stdlib implementation is exact. Signed 64-bit quantities in tables are carried by events as Unix seconds or split values that already fit; any future quantity that can exceed 2^53-1 requires a schema revision, not silent truncation.
- Key order is fixed by JCS, so re-encoding is byte-stable: a reader decodes, re-encodes and byte-compares to detect non-canonical input.
- `canonical_hash(bytes)` is SHA-256 over the exact canonical bytes.

Every payload schema below is closed: unknown members are rejected. Integer members outside the signed 53-bit range are rejected at the boundary.

## Mutation ports

Callers and error taxonomy follow [contracts](contracts.md#callers-and-service-surface) with these delivery deltas: the closed error code list for storage ports is `invalid_request`, `unauthorized`, `forbidden`, `not_found`, `stale_lease`, `conflict`, `source_blocked`, `invalid_evidence`, `identity_unresolved`, `temporarily_unavailable`. Route raises no storage error by design; the routing error codes (`invalid_request`, `invalid_snapshot`, `schema_incompatible`, `snapshot_unavailable`, `no_admissible_offer`) are owned exclusively by [educated routing](educated-routing.md) and no storage port raises them. No port raises `budget_exceeded`: a budget over limit is an admission rejection inside Route, never a storage error.

### Operator

- `register_source(Source)` / `revise_source(Source)`: unchanged from [contracts](contracts.md). Idempotent by source ID plus configuration hash. Emits `SourcePolicyChanged`.
- `set_publication_channel(channel, channel_class)`: creates or retires a publication channel lane. `channel_class` is `local` or `distributable`; retirement appends one `publication_channel_retirements` row carrying `retired_at`; publications require a lane with no retirement row. Idempotent: re-registering an identical open lane is a no-op; retiring an already-retired lane replays the stored `retired_at`. Changing the class of a live lane is `conflict` — retire and register a new lane. Response: the lane state. No domain event; infrastructure configuration.
- `record_terms_observation(source_id, terms_url, http_status, outcome, body_bytes, headers_bytes, retrieved_at, collector_version)`: unchanged from [contracts](contracts.md). Storage deltas: writes the immutable observation row and its hash-addressed `content_blobs` entry in one transaction; emits no outbox event (`ObservationRecorded` stays reserved for fetch-stage `record_attempt`), so no `stage_outputs` row or `output_id` reference exists for it. The pre-authorization path for source policy evidence per [source access](source-access.md).
- `register_projection_policy(version, content_bytes)`: persists one immutable projection policy. Validates that `content_bytes` are canonical-v1 (decode, re-encode, byte-compare), that their closed schema matches the projection policy grammar below and that `version` equals the version inside the content; stores `content_hash = canonical_hash(content_bytes)`. Idempotent by version plus content hash: identical replay returns the stored row; same version with different content is `conflict`; policies are never revised, only superseded by a new version. No domain event; infrastructure configuration matching `set_publication_channel`.

### Collector coordinator

- `enqueue_job(source_id, resource_url, stage, input_hash, parser_version)`: unchanged from [contracts](contracts.md). Stage tokens: `fetch`, `parse`, `resolve`, `compile`.
- `recover_job(job_id, expired_token)` and `reenter_job(job_id, new_input_hash, parser_version)`: unchanged from [contracts](contracts.md). `recover_job` is idempotent by expired token through the durable `job_leases.recovered_at` mark: the first recovery sets the mark and advances the attempt counter; replays derive and return state without mutation, and the expired-lease listing excludes marked leases so repeated reconciliation sweeps cannot re-adopt the same lease. Infrastructure transitions persist lease facts and the job attempt counter and emit no domain event; they write no `job_attempts` row because no worker attempt outcome exists — an attempt row exists only for a worker that actually observed something.

### Collector worker

- `lease_job(job_id, worker_id, lease_duration_seconds)`: unchanged from [contracts](contracts.md).
- `record_attempt(job_id, token, observation, assertions, coverage_findings, stage_output)`: the worker submits one typed stage output envelope. `stage_output` is `{output_id: string, output_bytes: canonical-v1 bytes}` matching the closed stage schema below. The port computes `output_hash = canonical_hash(output_bytes)`, stores the envelope through `stage_outputs`, the observation and assertions rows, and the `stage_output_links` row carrying the complete work tuple. Observation semantics are per stage: fetch creates the observation row and emits `ObservationRecorded`; parse and resolve create no observation — their envelopes carry the contributing fetch observation ID and the port emits `StageOutputRecorded` only; compile creates no observation and its link row carries a null `observation_id`. RecordAttempt is the durable-success path: every invocation produces a typed output envelope. Failed fetches, transient errors and blocked sources go through `defer_job` instead and produce no output envelope. Response: observation ID (absent for compile, which has no observation fact), accepted and quarantined assertion counts, output ID and output hash. Idempotent by the exact work tuple plus output hash: same tuple and same hash replays the stored result; same tuple and different hash is `conflict`. Independent of the retried lease token. Emits `StageOutputRecorded` then, for fetch only, `ObservationRecorded` in one transaction. Every submitted assertion `parser_version` must equal the job parser version; mismatch is `invalid_evidence`.
- `defer_job(job_id, token, outcome, detail, retry_not_before)`: `outcome` tokens are `deferred`, `quarantined`, `failed_terminal`. `deferred` requires a future `retry_not_before`; the other outcomes require `retry_not_before` equal to `observed_at` and represent terminal or blocked states that re-enter only through a new work tuple. Emits `JobDeferred` for `deferred`; quarantine and terminal failure persist attempt facts and emit no domain event because no dependency is released.
- `complete_job(job_id, token, output_id)`: requires the output already durably recorded by `record_attempt` for this exact job. Response completion ID. Emits `JobCompleted`.

### Evidence validators (collector service identity)

- `establish_revision`, `confirm_offer`, `withdraw_offer`: unchanged from [contracts](contracts.md); binding lifecycle ports remain owned by [temporal identity](model-identity.md#service-and-events).

### Publisher

- `compile_snapshot(inputs, distribution, projection_policy_version, created_at, knowledge_cutoff)`: `inputs` is the ordered list of `InputData` triples (observation ID, source ID, policy version); `distribution` is `local` or `distributable`; `created_at` and `knowledge_cutoff` are explicit caller-supplied UTC instants (millisecond-aligned), never taken from the port's wall clock — this keeps compilation deterministic and replay-independent, matching the no-caller-trusted-timestamp discipline of [temporal identity](model-identity.md#service-and-events). The applied projection policy version must exist in `projection_policies`; it owns signal weights, metric-to-task mappings and basis derivation, and is pinned into the snapshot row. Compilation requires, for every contributing source, the governing policy per [source access](source-access.md#precedence-and-conflict) — the greatest `effective_at` row of the current non-expired set, never an older allowed row beneath a newer denial — and that governing policy must have `research` and `extraction` allowed; `distributable` additionally requires `redistribution` allowed. Missing, expired, unknown or same-time conflicting policies exclude that source's inputs. Each input's `policy_version` must equal the authorizing policy's config hash. The port writes the artifact to staging, writes `snapshots`, `snapshot_inputs` (one row per input, ordered), `snapshot_rights_audits` (one row per contributing source pinning the authorizing `source_policies.config_hash` and the decision) and emits `SnapshotCompiled`. Response: artifact hash, artifact locator, coverage digest. Idempotent by the complete ordered parameter set — inputs, distribution, projection policy version, `created_at` and `knowledge_cutoff` — so an identical call replays the identical artifact bytes and hash without re-emitting; a different parameter set that produces identical artifact bytes collides on `snapshots.artifact_hash` and is rejected `conflict` (the table keys on the hash), and a concurrent identical compile replays the stored row. `coverage_digest` is `canonical_hash` of the canonical-v1 encoding of the ordered coverage array: one member per contributing coverage finding of the contributing observations, each `{subject_upstream_id, channel, outcome}`, sorted by `(subject_upstream_id, channel, observation_id)`, each key compared bytewise UTF-8 ascending (the same rule governs the snapshot-inputs ordering inherited from educated routing) — a total order even when two observations report the same subject and channel. Free-text `detail` is deliberately excluded so wording changes cannot alter the digest.
- `validate_snapshot(artifact_hash, validator_version)`: validates the staged artifact bytes against the artifact format below and the pinned rights audit. Response: outcome `accepted` or `rejected` plus safe findings. Emits `SnapshotValidated`. No publication on rejection.
- `publish_snapshot(artifact_hash, channel)`: `channel_class` is read from `publication_channels`, never supplied by the caller. Requires an accepted validation for this hash. A `local` artifact may publish only to a `local` channel; a `distributable` artifact may publish to either. Inside the one publication transaction the port re-evaluates current policies against the artifact's pinned distribution: any revocation committed before insertion fails the gate; a revocation committed after leaves the published artifact intact and excludes successor compiles. The persisted decision lands in `snapshot_publications.rights_decision` atomically with the publication row. Response: publication ID and artifact locator. Emits `SnapshotPublished`. Idempotent by artifact hash and channel.
- `retire_snapshot(artifact_hash, successor_hash, publication_id)`: unchanged from [contracts](contracts.md). Emits `SnapshotRetired`.
- `confirm_snapshot_freshness(artifact_hash, channel)`: appends a `snapshot_freshness_confirmations` row stamped at the port's transaction time. No event: a freshness confirmation is an infrastructure fact about an unchanged artifact, not a domain transition. Idempotent per (artifact hash, channel, instant).

### Successor pipeline (publisher service)

The publisher service identity runs one automated successor loop per configured channel, driven by the delivery outbox — never by a manual port call:

- **Triggers (first slice).** The consumer identity `publisher` scans events via `delivery_scan`; the eligible trigger vocabulary is `ObservationRecorded` with `outcome = 'success'`. Events outside the vocabulary are receipted without action. Processing is at-least-once with `record_consumer_receipt` as the durable progress mark.
- **Debounce.** One batch of triggers performs one successor attempt: the loop drains the scanned batch, resolves a single successor decision, then records receipts for the whole batch. A successor attempt that ends in publication, freshness confirmation or a semantic block (below) resolves its batch; an attempt that fails on a storage or transport error records no receipts, so the batch redelivers.
- **Input selection.** At attempt time the pipeline selects, per source with a governing policy allowing `research` and `extraction` (and `redistribution` when the channel carries a `distributable` artifact), the latest observation with `outcome = 'success'`, ordered by `retrieved_at` then `id` — the same precedence rule as claim ordering, breaking ties deterministically. Each selected input pins `policy_version` to the governing policy's `config_hash`. Sources with no success observation contribute nothing and are not an error.
- **Parameters.** The successor compiles with `distribution` and `projection_policy_version` inherited from the channel's current publication's snapshot; `created_at` and `knowledge_cutoff` both equal the attempt instant. Bootstrap — a channel with no current publication — compiles from the full selected input set using the daemon configuration's pinned `distribution` (first slice: `local` only) and `projection_policy_version`, which must already be registered.
- **Unchanged content.** The successor artifact is decoded, both artifacts are re-encoded with `created_at` and `knowledge_cutoff` replaced by the Unix epoch sentinel (both members are attempt-time metadata, not evidence), and the bytes are compared. Equal bytes mean no evidence or policy change affected the projection: the pipeline appends a `snapshot_freshness_confirmations` row for the current artifact, records receipts and stops. No new publication is made; the freshly compiled staging row remains as the audit trail of the check. The unchanged path still converges the local store and the retirement sweep before stopping, so a stale generation or an orphaned retirement heals here too.
- **Changed content.** The pipeline runs `validate_snapshot` with the configured `validator_version`; `rejected` is a semantic block — receipts are recorded, the rejection findings are logged through the loop's log hook, the prior generation stays current, and the next trigger re-attempts. `accepted` continues to `publish_snapshot` on the channel, then materializes the artifact to the local store (below), adopts it, and retires the predecessor via `retire_snapshot` naming the successor hash and the new publication ID. Retirement converges: every resolved attempt and every reconciliation retires any older publication on the channel that lacks a retirement row, naming the current publication, so a crash between publish and retire completes on redelivery or restart rather than being lost. A `publish_snapshot` failure that is semantic in kind (`forbidden`, `conflict` on a same-hash republication, `source_blocked`) resolves the batch as blocked and leaves the prior generation current. An attempt failing on a storage error writes no receipts and the loop backs off before the batch redelivers; a permanent `invalid_request` (misconfiguration) stops the loop loudly instead of hot-retrying.
- **Revocation after publication.** A published artifact and its local file remain readable for local routing; no destruction path exists. Revocation affects successors only: the input selection excludes the revoked source, the next generation omits its offers, and `publish_snapshot`'s in-transaction re-evaluation refuses any artifact that still pins the revoked source.

### Local artifact store

The local publication store is a filesystem projection of `snapshot_publications`; the database is the durable intent and the store is derived, rebuildable from `snapshots.artifact_bytes`:

- Layout: `<root>/snapshots/<hex(artifact_hash)>.bin` and `<root>/CURRENT`, one generation per file. `CURRENT` holds exactly the current artifact's hex hash and a trailing newline.
- Staging writes the exact artifact bytes to a temporary file in the same directory, `fsync`s it, and renames it onto the target path — the file either exists whole at its final name or not at all. Staging the same hash with identical bytes is a no-op; the hash pins the bytes.
- Adoption verifies the staged file exists and its bytes hash to the pinned hash, writes the new pointer to a temporary file, `fsync`s it, and renames it onto `CURRENT`. A reader that opens `CURRENT` and then the named artifact always sees a complete generation, possibly one behind the latest adoption. A malformed or empty `CURRENT` reads as absent — the store is a derived projection, so reconciliation heals it by re-adopting instead of failing.
- Retention keeps the current generation and at least `keep_generations - 1` predecessors (configuration floor 2). Pruning deletes only artifacts beyond the retention window that are not named by `CURRENT`; deletion never touches the `snapshots` or `snapshot_publications` rows.
- Reconciliation runs at daemon startup and after every adoption: for the configured channel it loads the latest publication by `published_at` (newest wins, ties by publication ID), stages its artifact from `snapshots.artifact_bytes` if the file is missing or corrupt, and adopts it if `CURRENT` disagrees. No transaction spans the database and the filesystem; reconciliation is idempotent and converges the store to the published truth after any crash between publication and materialization.

#### Publisher daemon configuration

`RunCollectorWith` runs the successor loop when the configuration carries a validator version: `snapshot_channel` (default `local`), `snapshot_validator_version` (required for the loop), `snapshot_projection_policy_version` (bootstrap and inherited), `snapshot_distribution` (`local` in this slice), `store_dir` (filesystem root; default `<os.UserConfigDir>/agent-routing/store`) and `store_keep_generations` (default 2, floor 2). The loop performs one reconciliation before its first scan and after each publication. No schedule drives the loop in this slice; evidence events do.

### Host outcome reporter

- `record_receipt(HostReceipt)`: the host adapter identity submits the receipt contract from [host integration](host-integration.md). The port stores the receipt bytes as a `host_local` observation with HTTP status 0 (no HTTP exchange exists; the value is an honest absence marker admitted by the status CHECK below, never a fabricated 200), the typed outcome fact with its validation split per the tables below, the usage facts split by knowledge, and emits `ReceiptRecorded`. Idempotent by receipt ID plus body hash; same ID with different bytes is `conflict`. Task prompts, images, file contents and tool outputs are rejected. `offer_id` is the runtime offer identity from the decision and carries no FK to `offers`: an unmapped live offer can be selected and routed under [educated routing](educated-routing.md) unscored fallback, so its outcomes must be recordable; the port validates it against the request's decision instead. Outcomes for unmapped offers inform no signal until the offer enters a snapshot through normal collection. Provider-reported completion may never be recorded as a validated outcome: a `validated_outcomes` row is written exactly when the receipt's outcome is `validated_success` or `validated_failure` and carries the naming `validator_version`, and authenticity of the validation claim itself is enforced by the host-reporter caller class, not by the schema.

## Event payloads

Envelope: `outbox_events` columns as in [contracts](contracts.md#domain-events). `payload` holds canonical-v1 bytes of the exact closed schema; `payload_hash = canonical_hash(payload)`. Every field below is a self-contained fact unless marked `row-reference`, meaning consumers must load the authoritative row for that aspect and that row's retention is bound to the event's usability.

- `SourcePolicyChanged`: `source_id`, `config_hash` (hex string), `enabled`, `research`, `extraction`, `redistribution`, `parser_version`. Self-contained.
- `ObservationRecorded`: `observation_id`, `source_id`, `resource_url`, `body_hash`, `outcome`, `collector_version`, `output_id` (row-reference to `stage_outputs`). Emitted only by fetch-stage `record_attempt`; host receipt observations are projected from `ReceiptRecorded` alone and never emit this event. Parser version is not an observation fact; it lives on assertions and jobs.
- `StageOutputRecorded`: `observation_id` (omitted for compile outputs, which have no observation fact — mirroring the findings precedent), `job_id`, `source_id`, `resource_url`, `stage`, `input_hash`, `parser_version`, `output_id`, `output_hash`. The complete durable work tuple plus output identity; consumers never dereference job counters to validate work. Self-contained.
- `JobDeferred`: `job_id`, `source_id`, `token`, `retry_not_before` (Unix seconds), `outcome`, `detail`. Self-contained.
- `JobCompleted`: `job_id`, `token`, `output_id`, `stage`. Self-contained.
- `RevisionEstablished`, `OfferListingChanged`: unchanged from [contracts](contracts.md).
- `SnapshotCompiled`: `artifact_hash`, `schema_version`, `policy`, `distribution`, `input_manifest_hash`, `coverage_digest`. Self-contained.
- `SnapshotValidated`: `artifact_hash`, `validator_version`, `outcome`, `findings_hash` (`canonical_hash` of `findings_bytes`). Self-contained.
- `SnapshotPublished`: `publication_id`, `artifact_hash`, `schema_version`, `policy`, `distribution`, `channel`, `channel_class`, `coverage_digest`, `artifact_locator`, `knowledge_cutoff` (Unix seconds), `published_at` (Unix seconds). Self-contained.
- `SnapshotRetired`: `retired_hash`, `successor_hash`, `publication_id`. Self-contained.
- `ReceiptRecorded`: `receipt_id`, `observation_id`, `offer_id`, `task`, `outcome`, `usage_hash` (content hash of the receipt's usage facts across `outcome_usage_known` and `outcome_usage_unknown`; consumers locate the rows by `receipt_id` through the two PKs). `usage_hash` is `canonical_hash` of the canonical-v1 encoding of one array of exactly seven members ordered by component (bytewise UTF-8 ascending): for each of the seven usage components a member `{component, value}` when the component is known and `{component}` when it is unknown — the absent fact is expressed by omitting the member, never by a null or a zero sentinel. Self-contained facts plus one reference.

Replay is at-least-once with consumer deduplication by event ID. Replay failure behavior: a consumer that cannot load a `row-reference` defers the event and keeps it visible; events are never silently dropped. Outbox rows and every row referenced above are retained while any consumer lacks a receipt.

## Snapshot artifact format

The artifact is the canonical-v1 encoding of the routing `SnapshotData` with these delivery facts: top-level members are exactly `schema`, `created_at`, `knowledge_cutoff`, `policy`, `distribution`, `inputs` and `offers`; `inputs` members are `observation_id`, `source_id` and `policy_version`, sorted by observation/source/policy as [educated routing](educated-routing.md) requires; `offers` members follow its OfferData with snake-case keys. `distribution` is `local` or `distributable` and is pinned into the artifact bytes. `InputData.PolicyVersion` is the hex `source_policies.config_hash` of the policy version that authorized that input's inclusion, exactly the version pinned in `snapshot_rights_audits`.

- Artifact hash is `canonical_hash` over the exact artifact bytes. `snapshots.artifact_hash` equals it; the Engine's decision snapshot hash equals it.
- Times serialize as RFC 3339 UTC strings with `Z` suffix and millisecond precision. Artifact integers must satisfy the signed 53-bit canonical range; `NewSnapshot` rejects out-of-range integers rather than truncating.
- `DecodeSnapshot` rejects: non-canonical bytes (re-encode mismatch), unknown or missing members, `schema` other than 1, `policy` other than `educated-v1`, more than 100000 offers, encoded size above 64 MiB, duplicate offer IDs and any value violating the educated routing constructors.
- Compatibility: schema 1 readers reject every other schema value with `schema_incompatible`. No minor-version compatibility exists in this delivery.
- `adopt_snapshot(artifact_bytes, expected_schema)`: host-local file read, canonical re-encode check, hash recomputation, bound checks, then atomic swap. Failure retains the prior generation and returns a safe error; the retained hash stays exposed through the engine's `ActiveHash` accessor. Local infrastructure operation; no Knowledge transition or event.

### Snapshot projection grammar (compile_snapshot)

The projection is deterministic from the snapshot-family tables plus the pinned `source_policies` and `projection_policies` rows, evaluated at `knowledge_cutoff` except where stated.

- Rights gate: for each distinct input source, the governing policy is the greatest `effective_at` row among rows with `effective_at <= created_at` and `expires_at > created_at`. No current row, or two rows sharing the greatest `effective_at`, excludes that source's inputs. The governing row must have `research` and `extraction` allowed; `distributable` additionally requires `redistribution` allowed; otherwise the source's inputs are excluded. Each input's `policy_version` must equal the hex `config_hash` of its source's governing row; a mismatch excludes that input. Contributing sources get one `snapshot_rights_audits` row each with the governing `config_hash`, the three permission values and `decision='allowed'`; excluded sources get no row and no inputs. An empty contributing set is legal (synthetic snapshot).
- Offer set: an `offers` row whose `catalog_observation_id` is a contributing observation and whose latest `offer_listing_facts` row by `observed_at` (ties resolve to `withdrawn`, conservatively) is `listed`. `OfferData.ID` is `provider || '/' || upstream_id`; `ModelID` is empty (no canonical model association exists in this delivery); `LatencyMillis` is 0 (unavailable); `Region` and `Privacy` are empty (unknown); `ConfirmedAt` is zero (unverified).
- Revision association: a binding is current at `knowledge_cutoff` when `effective_at <= knowledge_cutoff` and no `identity_binding_ends` row for it with `effective_at <= knowledge_cutoff` and no `binding_supersessions` row naming it `old_binding_id` with `effective_at <= knowledge_cutoff`. Exactly one current binding yields `OfferData.Revision` = that revision's `revision_name`; zero or more than one current binding yields the empty revision and no signals for that offer (identity ambiguity fails closed).
- Capabilities: sorted unique `capability_assertions.capability` tokens with `support='supported'`, subject matching the offer (`subject_upstream_id = upstream_id`), observed by contributing observations, and present in the routing capability vocabulary; unsupported and unknown rows contribute nothing.
- Limits, conservatively intersected per routing resource: `context_tokens`<-`context_tokens`; `input_tokens`<-`input_tokens`; `output_tokens`<-`output_tokens`; `input_images`<-`image_count` role `input_image`; `output_images`<-`image_count` role `output_image`; `references`<-`reference_image_count`; `image_width`/`image_height`<-the same names across all scopes and roles; `image_bytes`<-`image_bytes` across all scopes. For each resource, `maximum` is the minimum over all maximum and exact bounds (an exact bound contributes its value to both ends), subject to agreement of exact values; conflicting exacts, or a minimum above the derived maximum, omit the resource (unknown, never a fabricated intersection). `mask_count` and `image_pixels` have no routing resource and are not projected; they remain collector facts.
- Prices: `price_assertions` rows for the offer with `currency='USD'`, `unit='million_tokens'`, `quote_knowledge` in (`exact`,`proven_upper_bound`) and `category` in the routing price component vocabulary. The amount is carried as its exact decimal lexeme with trailing zeros trimmed; multiple admissible quotes for one component take the greatest amount (upper-bound semantics); disagreement between `exact` quotes for a component omits the component (unknown).
- Signals: one signal per `benchmark_measurements` row whose revision has exactly one current binding to the offer, where `task_map` maps `benchmark_label` to a routing task and `weights` carries that task (weight 1..10000). Value is `round(raw_value * 100)` for unit `'%'` (basis points) and the integral `raw_value` otherwise; values outside 0..10000 are skipped. `Basis` is `basis_rules[evidence_class]` of the measurement's assertion when present, else `published`. `EvidenceID` is the measurement assertion ID, `Revision` is the bound `revision_name`, `Warnings` is empty at this layer. `zero_image_charge_evidence` is carried by the policy and gates image cost admission in routing, not the projection.
- `snapshot_inputs` ordinals follow the artifact's sorted input order. The coverage digest and input manifest hash follow the compile port recipe.

## Stage output envelopes

`stage_outputs.output_bytes` is the canonical-v1 encoding of one closed schema per stage; the `stage` member inside the bytes must equal `jobs.stage` and a mismatch is `invalid_evidence` at ingestion. One output per job: `stage_outputs` is keyed on `job_id` alone, so replay with the identical work tuple adopts the stored row and a different hash for the same job is `conflict`. A fetch whose bytes disagree with a stranded output (crash between record and completion, upstream bytes changed) is neither adoptable nor a transport retry: the worker defers with backoff and a durable `deferred` attempt row naming the conflict, pending disposition, so the disagreement is visible and rate-limited rather than an unbounded refetch loop.

- fetch: `{stage, observation_id, resource_url, body_hash, http_status, headers_hash}` — a typed descriptor of the observation this job creates; `headers_hash` is `SHA-256(observations.headers_bytes)`; raw bodies live in `content_blobs` keyed by `body_hash`, never in the output bytes.
- parse: `{stage, observation_id, assertion_ids}` — the contributing fetch observation plus ordered IDs of the assertions created from its body. Creates no observation row.
- resolve: `{stage, observation_id, finding_ids}` — the contributing fetch observation plus ordered IDs of the `coverage_findings` rows recorded for its unresolved labels; a resolve-stage finding carries outcome `researched` (label resolved to a canonical identity) or `identity_ambiguous` (conflicting or insufficient evidence), never the other tokens. Coverage findings are the durable storage of resolution outcomes, no separate proposal table exists. Creates no observation row.
- compile: `{stage, artifact_hash}` — the compiled snapshot identity; the artifact bytes live in `snapshots`. Creates no observation row; the link's `observation_id` is null.

That origin constraint needs the `sources` row and cannot be a column CHECK: fetch ports never write success with 0, the `record_receipt` port writes it only for `host_local` receipts, and the validation sweep named in the cross-check gate re-verifies it. For remote observations status 0 denotes a transport failure with no HTTP status; `quarantine` is administrative and pairs with any status.

## Job state derivation

`jobs` stores no state column. Deterministic state, evaluated on the locked job row:

1. `completed` if a `job_completions` row exists.
2. else `quarantined` if the latest attempt by `(observed_at, token)` has outcome `quarantined` or `failed_terminal`.
3. else `deferred` if the latest attempt has outcome `deferred` and its `retry_not_before` is in the future.
4. else `queued` if no lease exists or the latest lease `expires_at` has passed.
5. else `leased`.

Transitions map to aggregate methods in [domain model](domain-model.md#collectionjob). Lease expiry reconciliation and retry deadlines are the only timer-owned work. The claimable scan joins `sources.enabled`: a disabled source stops dispatching its in-flight jobs. Quarantined and terminal jobs re-enter exclusively through `reenter_job` with a changed input hash or parser version.

## Signal derivation basis

Snapshot signals derive only from permitted sources: assertion `evidence_class` `provider_reported` yields signal basis `publisher_claim`; `third_party_reported` and `competitor_reported` yield `published`; `outcome_facts` rows yield `host_observed`. Projection policy versions own weights and metric mappings; this mapping is the only permitted basis derivation and is enforced at compile validation.

## Cross-check gate

Every port maps to its tables and events as named above. Before implementation: instantiate this schema on real Postgres with every CHECK, UNIQUE, FK and trigger; replay every event sequence including duplicate events, stale leases, crash between output and completion and revocation before publication; verify canonical byte stability across decode and re-encode; verify the artifact format and `coverage_digest` against independently encoded fixtures; and confirm the five deferred validations — seven usage components per receipt exactly once across `outcome_usage_known` and `outcome_usage_unknown`, the `validated_outcomes` child-row pairing (both directions, rejecting an unvalidated relabel and a child-less validated parent), the publication channel class and retirement match, the stage-kind match between stored output bytes and `jobs.stage`, and success-with-status-0 only on `host_local` observations. Calibration tables remain outside this delivery and nothing here creates them.
