# Local subagent router

Draft contract, pass 1. Superseded for the implemented slice by [educated routing](educated-routing.md) under ADR 0003; retained as the future calibrated-lane draft. Go is the requested implementation language, not a measured speed advantage over another language. No implementation exists. Proposed performance bar: warm embedded route p99 under 1 ms for 10,000 offers and 100 candidates, measured on the target Mac with explanations enabled. Report cold load, reload time, allocations and memory separately. No network, database reads or inference on the route path.

## Routing boundary

Embed a Go library in the host. A CLI is a proposed thin testing/early integration adapter, not the normal invocation. CLI invokes the same public API; no ranking or policy logic duplicated in it. Pi or another harness supplies its live model registry, capabilities, authentication eligibility and runtime limits. Registry IDs are translated at the adapter boundary. Catalog membership does not grant credentials or establish account access. The router returns an admissible ranked selection and reasons; the host owns spawning, tools, retries, evaluation, cancellation and receipts. No new agent identity or execution service is needed.

Collector authority lives in Postgres. A versioned immutable file contains the local routing projection. Load once and swap a fully validated replacement atomically; active calls retain their prior generation. SQLite is only the requested research artifact, not a production route-time dependency. In-memory indexes, precomputed capability bitsets and task-dimension evidence are enough. Use stdlib-first Go (encoding/json, sync/atomic for snapshot publication) before adding custom storage or indexes.

Dependency candidates not selected: stdlib encoding/json, sync/atomic for snapshot publication, exact money via scaled integers or math/big. No new dependencies installed and no speed claims. No custom vector database, model registry or task-classification LLM on the hot path.

## Request

`RouteRequest` is a value object with these complete fields:

- `request_id`: host correlation string, no prompt content.
- `task`: closed task family plus weighted dimensions. Initial families: code edit, repository analysis, code review, tool-driven workflow, reasoning, extraction, writing, translation, vision understanding, image generation and image editing. Unknown family uses general assistance, not guessed specialist strengths. Weights are finite, nonnegative and sum to one.
- `requirements`: input/output modality sets, required tools/structured output, estimated input/output token bounds, minimum context, supported reasoning configuration, region, privacy/retention rules and allowed providers. Operation is a closed sum: text assistance; vision understanding with input images; generation with output images; editing with input images, optional mask and output images. An image specification includes image role, direction, accepted format (`png`, `jpeg`, `webp`, `avif` or explicitly advertised format), width/height bounds, byte bound and count. Editing additionally requires advertised edit operation, reference-image count, mask format/dimensions and alpha support when needed. Offer assertions independently record input modality and output modality plus these limits. Text tokens, input image tokens/pixels, output image tokens/pixels, image count and steps have separate usage bounds. Unknown image accounting fails strict budget admission. Context-window accounting is not assumed input-only: each bound declares input, output or combined scope, and unknown combined accounting fails strict token admission. Legal role/scope/operation facts and admission are defined exclusively in [image capability contract](image-capabilities.md). Fields not applicable to the operation are expressed by its tagged variant, not ambiguous nulls.
- `budget`: maximum USD micro-units, billing regime and cost strictness. Public list price, subscription quota and local resource cost are distinct regimes. Incomplete estimates cannot pass strict cost admission.
- `quality`: minimum calibrated task success lower bound, evidence tier and `unknown_quality` policy (`reject` or `allow_fallback`). Without a calibration, published benchmark points cannot masquerade as a success probability.
- `latency`: completion deadline in milliseconds and latency strictness. Unknown latency cannot pass a strict deadline.
- `mode`: `cost` or `performance`.
- `fallback`: permitted relaxations, maximum attempts and maximum accumulated spend. Relaxation never includes hard modality, credential, privacy, region or budget constraints.
- `runtime`: a complete host registry generation, eligible offer IDs, account entitlement facts, observed health generation and device/admission restrictions. No secrets.
- `snapshot`: expected schema compatibility and minimum freshness policy.

Constructor rejects incompatible operation/modality combinations, invalid bounds, negative money, unsupported privacy expressions, duplicate offer IDs and invalid task weights. Unknown capability evidence remains unknown. An empty eligible registry produces no selection.

## Selection

1. Intersect local offers with the host's live eligible registry. Unmapped live models remain visible as unknown candidates, never silently removed from diagnostics.
2. Apply hard requirements: modalities, tool-use, structured output, operation settings, provider/region/retention, context/output limits, entitlement and resource admission. Require verified support, not absent flags interpreted as false or true. Gateway and direct-provider restrictions remain offer-specific.
3. Resolve offer identity using [temporal identity](model-identity.md#deterministic-resolution), with current effective time and pinned snapshot knowledge/policy versions. Unknown/ambiguous identity excludes revision-derived traits and quality, while verified offer facts can support explicit unknown-quality fallback. Historical benchmark identity never follows the current alias. Classify evidence under [benchmark comparability](benchmark-comparability.md#eligibility-and-critical-components). Only verified same-cohort facts support descriptive numerical comparisons. Unknown critical metadata never equals known or unknown metadata. Raw values stay displayable. Published percentages, Elo and pass@k do not become calibrated success or quality-floor credit. Missing statistical facts supply no confidence bounds. Provider claims remain descriptions, not measurement credit.
4. Estimate a bounded total cost using exact decimals and all applicable price components. Include cached/uncached input, reasoning output, searches, image operation and provider-varying prices. Default to zero cache hits unless the host proves reuse. An incomplete estimate is explicit. A deadline estimate includes queue time, first-token latency and generation time, with observation sample size and age.
5. Enforce quality, budget and deadline admission. Unknown quality may enter only the explicit fallback pool; it cannot satisfy a numeric floor. No calibrated candidates and a strict quality floor produce `no_admissible_offer`.
6. In cost mode, minimize conservative total cost among candidates meeting the quality floor; tie-break by calibrated quality lower bound, estimated completion time and stable offer ID. In performance mode, maximize calibrated quality lower bound under hard limits; tie-break by completion time, cost and stable offer ID. Unknown candidates are a separately labelled fallback class, not a synthetic midpoint quality score. Deterministic ordering applies even when all estimates are unknown.
7. Return the chosen offer/configuration, ordered admitted alternatives, rejected-candidate reasons, price interval/completeness, quality basis, latency estimate, field freshness, coverage warnings, runtime generation and snapshot/policy hashes, identity cutoffs and source-run/comparison-policy evidence. Raw, comparable and calibrated classifications are distinct tagged results, not one quality number. A degraded result names its explicit relaxations. Include source evidence IDs so explanations are auditable without remote fetches.

The quality floor, task weights, freshness limits and calibration thresholds are proposed policy inputs, not settled product defaults. Public benchmarks seed discovery and explanations. Reliable task-success estimates require calibration against representative local work. Until then the honest mode is explicit evidence-based ranking without a numeric success guarantee, with strict quality-floor requests rejected.

## Delegation and feedback

Router does not claim to understand task difficulty from a paragraph. Host supplies structured task requirements from tool context, file/task size and workflow role. A deterministic local classifier may suggest dimensions later, but its uncertainty is part of the request. No cloud classifier latency is hidden in the routing budget.

Host can request parallel selections with an admission reservation and total spend bound. Distinctness may be by offer or underlying model revision; two providers of the same model are not independent reviewers. Reservations, rate limits and local GPU/device leases are host-owned hard eligibility facts. Router never starts a GPU job itself.

A result includes fallback candidates; on failure the host reports a classified outcome and re-routes against updated health/budget. Preserve total attempts and spend across restarts. Context-window failures trigger token/context re-estimation, not blind repeated retries. Auth failures disable that account offer until credentials change. Rate limits obey provider deadlines and circuit-breaker state. Safety refusals do not authorize routing around a policy restriction.

Outcomes carry task family, selected revision/offer/configuration, measured tokens/cost/latency, validator version, success/failure category and evidence quality. Usage is a finite set of known components with direction and bounds: text tokens, image tokens, pixels/megapixels, image count, steps, search requests and elapsed seconds. An unknown component is recorded as unknown, never zero. Failed/cancelled image operations still record any billed input/output usage. Calibration remains disabled until the typed receipt/schema contract is accepted. Store no prompts, files, images or tool outputs by default. Provider-reported completion is not task success. Automatically evaluate mechanically checkable work using its real tests or schema. Human corrections and model-based judges have their own bias/provenance tier. Feedback updates a later snapshot, never nondeterministically changes an in-flight route.

## Failure behavior

Corrupt or incompatible snapshot: retain last known good generation. Adoption checks schema, hash and rights, then labels per-fact ages. Route admission rechecks freshness against the current clock on every invocation; keeping an integrity-valid generation never refreshes stale facts. No usable snapshot: return `snapshot_unavailable`, not a hardcoded model. Stale price under strict cost policy: reject affected offers. Partial collection outage: retain unaffected facts with their own ages. Unknown capabilities: reject hard-requirement admission. Runtime offer removal wins immediately over catalog data. New offer without benchmarks can enter an explicitly permitted exploratory fallback, never displace a proven candidate by treating missing data as perfect performance.

Do not relax privacy, data residency, credential access, required operation or maximum accumulated spend. Explanations contain policy decisions and public evidence IDs, never account secrets. Remote bundle distribution requires a separately accepted trust policy; unsigned internet artifacts are not trusted.

## Acceptance measurements

Replay synthetic and real host requests against a frozen snapshot; require stable bytes after excluding request correlation. Test candidate addition/removal, account access changes, concurrent swaps, rollback, partial pricing, ambiguous identities and fallback accumulation. Drive the actual host's subagent spawn using the returned offer and capture outcomes. Test text-only, vision-input, image-output and image-edit operations independently. Measure route p50/p95/p99 at 1,000 and 10,000 offers, with concurrent readers, reloads and explanations. Go speed, task quality and end-to-end agent latency remain unverified until these paths run.
