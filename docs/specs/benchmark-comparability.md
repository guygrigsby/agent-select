# Benchmark evidence and comparability

Proposed contract. Owns raw measurement and comparison metadata payloads/tables referenced by `contracts.md`. Defines no calibration algorithm. A recorded percentage, Elo rating or pass@k is not a task-success probability.

## Evidence objects

SourceRun is an immutable value object owned by SourceObservation. Fields: `id`, `observation_id`, `locator`, `identity_kind: publisher_run|source_record`, `identity_value` and `content_hash`. A publisher run ID is retained exactly. A source-record identity hashes an immutable observation plus source table/row scope; it identifies the publication record, not proof of a reproducible experiment. Source run identity and cohort identity are different. A source-record key can support raw evidence; comparison additionally requires a verified evaluation protocol.

Measurement is an Assertion-owned immutable value object. Fields: `assertion_id`, `run_id`, `benchmark_label`, `metric_label`, `raw_value: exact decimal`, `unit` and `direction: higher|lower|unordered`. Its common assertion subject retains the publisher's exact reported model label. No revision FK is required for raw storage. A separate evidenced identity-resolution fact attaches an exact immutable revision when established. Unknown identity does not become the current alias destination.

ComparisonMetadata contains independent known/unknown/not-applicable markers for every policy-required component. Known values, unknown reasons and not-applicable evidence occupy separate child relations. No column changes meaning with a sibling state. Missing metadata must be represented as unknown before comparison, not replaced with an implicit default. A finite policy vocabulary and canonical value type define each component. Source text/value bytes remain evidence; configuration values queried for equality are canonical typed facts, not JSON or arbitrary payloads.

## Eligibility and critical components

Raw display requires a sourced value, label, unit and metric. Incomplete settings remain visible. Within-cohort comparison additionally requires exact revision resolution for each candidate and all critical components known or evidenced not-applicable. Unknown versus unknown never establishes equality. Calibration remains a separate disabled lane until an empirical outcome contract is accepted.

Common critical components: benchmark release/version, split, protocol/harness version, metric/unit/direction, prompt/template, shots, active decoding/sampling policy and generation count, output/compute budget, reasoning effort where applicable, tool policy and precision/quantization where applicable. Model revision is a prerequisite but excluded from the cohort key; otherwise two different models could never share a cohort. Individual run ID and actual random seed are also excluded; the seed distribution/policy remains critical. Hardware is critical for latency/resource metrics, not automatically for static accuracy.

Family-specific additions:

- Code/repository: task-set/base revision, agent scaffold/version, evaluator/test environment, language/runtime and patch/attempt limits.
- Reasoning/extraction/writing/translation: task language and evaluator/rubric/judge version where judged.
- Vision input: preprocessing, resolution/crop policy, input-image count and evaluator version.
- Image generation: prompt-set revision, output dimensions/count, sampler/steps/guidance, generation settings, safety/filter policy and evaluator/rating protocol. Image editing additionally requires operation and input/reference/mask policy.
- Preference/arena: candidate-pool identity, pair sampling/vote weights, rating algorithm/version and exact evaluation window.
- Latency/resource: hardware, provider/region/service tier, concurrency/queue policy and evaluation window.

Every required family component is individually named in the versioned policy. A benchmark-specific policy may declare a component not-applicable only with a documented rationale/evidence, not omit it silently. Static accuracy runs with identical fixed benchmark/protocol may compare across known or unknown calendar dates because dates are noncritical for that policy. Arena and latency windows are critical; unknown or differing windows prohibit comparison. Vision, generation, editing, preference and code remain separate families. Pass@1 and pass@k, raw accuracy and F1, or Elo and percentage never pool merely because their numbers fit the same range.

Derive cohort hash from policy version, canonicalization version and ordered canonical critical component/value pairs plus family and metric/unit/direction. Exclude model/run IDs. Different source runs may share a cohort when their verified critical facts match. Equal hashes are only an index: validate completeness and canonical facts as well. Raw-only values have no cohort membership row. A descriptive strength/weakness additionally needs a named within-cohort task threshold policy. Missing coverage is not weakness.

Sample count and uncertainty are separate source facts. Count alone supplies no confidence interval. Missing statistical information permits raw display and eligible descriptive comparison but forbids statistical confidence bounds or invented calibrated quality.

## Relational contract

All columns are NOT NULL. TEXT IDs, NUMERIC decimals, TIMESTAMPTZ instants and BYTEA hashes of length 32. All FKs are restrictive. PK indexes serve object/child lookups. Evidence is append-only; retractions use common assertion retraction. Cross-row subtype/completeness checks require deferred constraints and publication validation.

- `benchmark_runs`, SourceObservation-owned: `id TEXT PK`, `observation_id TEXT FK observations`, `locator TEXT`, `identity_kind TEXT CHECK IN ('publisher_run','source_record')`, `identity_value TEXT`, `content_hash BYTEA`; UNIQUE `(observation_id,locator,identity_kind,identity_value)`. Index `(identity_kind,identity_value)` serves publisher/source record resolution. Source_record is never relabelled reproducible.
- `benchmark_measurements`, Assertion-owned: `assertion_id TEXT PK FK assertions`, `run_id TEXT FK benchmark_runs`, `benchmark_label TEXT`, `metric_label TEXT`, `raw_value NUMERIC`, `unit TEXT`, `direction TEXT CHECK IN ('higher','lower','unordered')`. Index `(benchmark_label,metric_label,unit,direction)` serves raw evidence grouping. No model_revision_id or hidden current-alias join.
- `measurement_revision_facts`, Measurement-owned: `assertion_id TEXT FK benchmark_measurements`, `revision_id TEXT FK model_revisions`, `identity_evidence_id TEXT FK assertions`; PK `(assertion_id,revision_id,identity_evidence_id)`. Index `(revision_id)` serves revision provenance. More than one supported distinct revision prevents comparison; absence means unresolved.
- `benchmark_metadata`, Measurement-owned: `assertion_id TEXT FK benchmark_measurements`, `component TEXT`, `knowledge TEXT CHECK IN ('known','unknown','not_applicable')`; PK `(assertion_id,component)`. Index `(component,knowledge)` serves missing-critical checks. Component vocabulary is the finite policy vocabulary.
- `benchmark_known_values`, Metadata-owned: `assertion_id TEXT`, `component TEXT`, `canonical_value TEXT`, `evidence_locator TEXT`; PK/FK `(assertion_id,component)` to benchmark_metadata. Canonical value has the fixed per-component type/grammar defined in policy, such as integer count, bounded decimal, immutable artifact ID or closed enum. No JSON serialization. Known marker requires exactly one known-value row and no unknown/not-applicable child.
- `benchmark_unknown_reasons`, Metadata-owned: `assertion_id TEXT`, `component TEXT`, `reason TEXT`; PK/FK `(assertion_id,component)` to benchmark_metadata. Unknown marker requires this child only.
- `benchmark_not_applicable_facts`, Metadata-owned: `assertion_id TEXT`, `component TEXT`, `rationale TEXT`, `evidence_locator TEXT`; PK/FK `(assertion_id,component)` to benchmark_metadata. Not-applicable marker requires this child only and policy permission.
- `benchmark_run_periods`, SourceRun-owned known fact: `run_id TEXT PK FK benchmark_runs`, `started_at TIMESTAMPTZ`, `ended_at TIMESTAMPTZ`, `evidence_locator TEXT`; CHECK started<=ended. Index `(started_at,ended_at)` serves window matching. Absence records unavailable dates through metadata; no fake dates or null endpoint fields. Partially published dates are preserved as source evidence but do not establish a complete period.
- `benchmark_cohort_policies`, immutable configuration VO: `version TEXT PK`, `family TEXT`, `canonicalization_version TEXT`, `content_hash BYTEA UNIQUE`, `recorded_at TIMESTAMPTZ`; CHECK family declared enum. PK serves pinned policy lookup.
- `benchmark_cohort_rules`, policy-owned: `policy_version TEXT FK benchmark_cohort_policies`, `component TEXT`, `value_type TEXT`, `critical BOOLEAN`, `not_applicable_allowed BOOLEAN`, `rationale TEXT`; PK `(policy_version,component)`; CHECK finite component/value-type vocabulary. PK serves component completeness/type validation. Policy hashing covers its ordered rules.
- `benchmark_cohort_memberships`, deterministic derived Measurement-owned fact: `assertion_id TEXT FK benchmark_measurements`, `policy_version TEXT FK benchmark_cohort_policies`, `cohort_hash BYTEA`; PK `(assertion_id,policy_version)`. Index `(policy_version,cohort_hash)` serves comparable candidate lookup. Insert only after exact revision, critical metadata and hash validation. Unknown/ambiguous evidence has no row, not a misleading hash of unknown placeholders. A retraction invalidates use in successor projections without rewriting historical membership.
- `measurement_sample_counts`, Measurement-owned: `assertion_id TEXT PK FK benchmark_measurements`, `count BIGINT CHECK >0`, `evidence_locator TEXT`. Absence is unpublished count, not zero.
- `measurement_intervals`, Measurement-owned: `assertion_id TEXT FK benchmark_measurements`, `method TEXT`, `confidence NUMERIC CHECK >0 AND <1`, `lower_bound NUMERIC`, `upper_bound NUMERIC`, `evidence_locator TEXT`; PK `(assertion_id,method,confidence)`; CHECK lower<=upper. Published unspecified-confidence bounds remain raw evidence until their statistical meaning is established.
- `measurement_standard_errors`, Measurement-owned: `assertion_id TEXT FK benchmark_measurements`, `method TEXT`, `standard_error NUMERIC CHECK >=0`, `evidence_locator TEXT`; PK `(assertion_id,method)`. Count, interval and standard error do not imply each other's presence.

Markers and child types are validated exactly. Tables have no additional indexes beyond named query indexes and PKs. No alternate `measurement_assertions`, `evaluation_configuration_items`, generic configuration hash or conditional sample table remains active.

## Service and event cross-check

`record_attempt` already defines worker caller, lease authentication, source authorization, idempotency and errors. Its Measurement payload now carries the complete SourceRun, raw Measurement and explicit metadata marker/known/unknown/not-applicable children, known period and published statistical children. `invalid_evidence` rejects numeric/source/child inconsistencies. Unknown settings do not reject honest raw capture. SourceObservation.Record commits runs/assertions/children as immutable output with existing ObservationRecorded and StageOutputRecorded; payloads reference observation/output IDs so consumers load complete typed children. No new mutable measurement aggregate is required.

`classify_measurement(assertion_id,policy_version,knowledge_cutoff)` is a read-only Publisher/Host-adapter local port invoking BenchmarkComparison.Classify. Response separately reports raw-display eligibility, comparison eligibility/reasons, resolved revision evidence, optional derived cohort result and available sample/uncertainty facts. It never returns calibrated success. Errors: invalid_request, forbidden, invalid_evidence or identity_unresolved. Idempotent for immutable inputs and cutoff; no domain mutation/event. Snapshot Compile materializes only classifications validated for its pinned inputs/policy. The emitting transition/events remain SnapshotCompiled/Validated, with metadata-policy version and manifest hash included. Retraction or policy change triggers a successor, not mutation of old measurements.

Operator registers immutable cohort policy/configuration through the existing configuration authorization boundary. Recording a policy has no measurement/domain lifecycle event; the collector's durable configuration-change notification invalidates affected projections. The policy version/hash must be part of compile inputs and snapshot validation. Routing accepts only compatible same-cohort evidence for descriptive numerical comparison. Statistical or quality-floor admission stays disabled without accepted calibration.

## Verification cases

Different model IDs and run IDs with identical verified critical protocol share a cohort. Unknown-critical versus unknown-critical stays raw-only. Static accuracy protocol does not require matching calendar dates; preference or latency does. Changing split, metric, budget, precision or a critical family component changes cohort. Source-record identity alone does not prove reproducibility. Unresolved model label permits raw storage but no membership. Sample count without uncertainty creates no bounds. Image generation never substitutes for vision-input or editing evidence.
