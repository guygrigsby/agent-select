# Evidence collection pipeline

Draft contract, pass 1. No collector is implemented. Research snapshots are local evidence, not a claim that every published result has been found. Source access research lives in [catalog sources](../research/catalog-sources.md) and [benchmark sources](../research/benchmark-sources.md).

## Coverage contract

Discover every Vercel catalog entry. Research language models and image generation now, including language entries with image output. Retain other entry types without treating embeddings, rerankers, audio or video models as subagents. Input vision and image output are separate capabilities. Each discovered model gets a coverage row for each applicable source channel, even when evidence is unavailable.

“All published scores” means all numeric results discovered within the versioned source inventory for an exact model revision. It cannot mean the entire web has been exhaustively searched. Coverage reports name checked sources, successful retrievals, extraction versions, blocked sources, identity ambiguities and unresearched channels. New channels expand coverage without rewriting history. Missing benchmarks are not zero scores. Provider prose is a claim, not independent evidence of competence.

## Sources and precedence

1. Vercel public models endpoint: discovery IDs, offer-scoped capabilities, advertised limits and prices. Preserve every field, including unknown extensions. A public list does not prove account access, underlying provider selection or edit support.
2. models.dev API and repository: provider offers, canonical IDs when supplied, costs, limits and modalities. Join exact Vercel IDs within its Vercel provider first. Other providers are different offers, not alternate quotes for the Vercel offer.
3. Provider APIs, release pages, system/model cards, repositories and weight-hosting cards: direct capability statements and provider-reported benchmark tables. Follow release links automatically. Revision identity must be explicit.
4. Independent evaluation registries: benchmark results with model revision, harness configuration and source terms. Prefer official exports, versioned repository data and documented APIs. HTML parsing is a monitored fallback, never an assumed stable API.
5. Host observations and controlled evaluations: actual subagent outcomes, effective cost, provider latency and availability. Keep these separate from public benchmark measurements.

Authority is field- and offer-specific. Provider-offer metadata can override generic model traits only for that offer and only with its own evidence. Independent scores do not erase vendor scores. Conflicting numeric results coexist under their run/configuration identities. An ambiguous conflict excludes the affected field from strict routing. Store selection decisions as derived, versioned projections, not rewritten source facts.

## Identity resolution

Represent a model revision separately from a provider offer and from a mutable alias. Exact `(source, upstream_id)` joins are allowed inside a source. Cross-source resolution requires an upstream canonical ID or an explicit publisher alias statement. Case, punctuation and display-name normalization may generate candidates, never approve a match. Preview, quantized, distilled, fine-tuned, reasoning-effort and dated variants do not silently collapse.

Mutable aliases use append-only offer bindings with effective and recorded times, explicit ending/supersession facts and pinned authority/freshness policies from [temporal identity](model-identity.md). A new observation alone cannot end a competing binding. Bind evidence to the revision named at evaluation time, not the alias's current destination. Anonymous or unrevealed arena names remain unresolved. An identity resolution outcome is recorded as a `coverage_findings` row (outcome `researched` or `identity_ambiguous`) carrying both source locators and a reason. Accepted mappings survive new arrivals only while their identity evidence remains valid. Ambiguity is quarantined automatically; a new provider ID stays routable under its own identity if hard capabilities are known, but inherits no benchmark score.

## Event-driven collection

Run continuously under a supervised service with durable state. Upstream webhooks and repository push signals enqueue source checks. Where no event feed exists, adaptive conditional GET is the fallback: catalog/pricing checks initially hourly, public eval repositories daily and unchanged release indexes weekly. These are proposed ceilings, not implemented schedules. Decrease frequency on prolonged unchanged data, respect cache headers and freshness ceilings, and add jitter. A restart resumes outstanding work without a manual kickoff.

Stages:

1. Discover sources and entries. Persist registry changes and enqueue only affected source/model pairs.
2. Fetch conditionally using ETag or Last-Modified when offered. Save exact response bytes, response status, relevant headers, URL, retrieval time and SHA-256 before parsing. A `304` records a new observation referencing the prior bytes. Content hashes deduplicate bytes, not observations.
3. Validate source shape and size. New fields are preserved, not silently discarded. Missing required fields, implausible bulk deletions, HTML returned as JSON and source-type changes quarantine the observation and retain last known good facts.
4. Parse deterministic structured APIs, repository tables and model-card sections. Emit assertions pointing to an immutable source observation and a locator. Keep parsing version and source content hash in the idempotency key.
5. Resolve exact identities. Record unresolved candidates separately, with no inherited quality score. A coverage item becomes identity-blocked rather than researched-and-empty.
6. Extract remaining unstructured tables using change-triggered, bounded inference only if enabled. Send sanitized content, not credentials or task prompts. Require schema-valid rows, verbatim evidence spans, exact decimals present in source and explicit identity/configuration. Deterministic post-validation rejects changed numbers, unsupported model mappings and invented configurations. Never ask an agent to write an ungrounded “strength profile”. Keep this lane optional and cost-capped; deterministic collection continues if it is unavailable.
7. Normalize units and dimensioned prices. Preserve original decimal, unit and configuration. Calculate comparable projections without overwriting the original.
8. Reconcile projections and compute coverage deltas. Changed facts produce downstream invalidations; unchanged hashes do not trigger extraction or publishing.
9. Compile a deterministic routing snapshot, run consistency and replay tests, then publish a content-addressed artifact. Router readers adopt only validated versions atomically. Failed builds leave the prior version active.

Fetch and parse across independent hosts concurrently. Use a per-host limiter shared across all workers: one active request and at least one second between requests initially, or the stricter publisher limit. Bound total concurrency separately. A descriptive User-Agent identifies the collector. Honor `Retry-After` in seconds and HTTP-date form, exponential backoff with jitter otherwise. `429`, timeouts and `5xx` defer one source, not the whole sweep. Persistent `401`/`403`, captcha or robots restrictions mark access-blocked without circumvention. No undocumented endpoint discovery loops.

Durable work identity is `(source_id, resource_url, input_hash, parser_version, stage)`. The delivery pins exactly four stage tokens — `fetch`, `parse`, `resolve`, `compile` — in [delivery storage](delivery-storage.md); the `resolve/validate` mention below is historical and folds into `resolve`. For fetch, `input_hash` hashes the persisted source-change signal or revalidation deadline ID plus source configuration, not an unknowable future response. For parse, it is the response body hash; a `304` references the prior body and schedules no duplicate parse. For resolve/validate, it hashes the ordered assertion IDs and resolver/validator policy version. For compile, it hashes the ordered input manifest and policy/calibration versions. A new signal, changed bytes or new parser/policy creates a distinct work identity.

A leased job has a fencing token; expired leases are reclaimable and stale workers cannot acknowledge. Each aggregate commits its facts and its own outbox event atomically. Stage completion is a durable choreography, not a multi-aggregate transaction: record immutable output plus an output-to-job link and `StageOutputRecorded` atomically; its idempotent consumer records the job attempt/completion with the active fencing token; only `JobCompleted` releases dependencies. The output link includes the exact work identity. After a crash, undispatched outbox events and links without matching completions are replayed. An expired token cannot complete a job; its new lease may adopt an already validated output for the identical work tuple. `record_attempt` returns durable output acceptance, never uncommitted next work IDs. Delivery is at least once; consumers deduplicate by event ID. Dependencies, not polling workers, release the next stage. Retry deadlines are the only timer-owned work apart from conditional source checks. Dead-lettered items stay visible in coverage and automatically re-enter when their source or parser changes.

## Benchmark evidence

A measurement contains exact model revision, benchmark name/version, metric, raw decimal/unit, direction, evaluation configuration, reported score provenance and source span. Configuration includes harness commit, agent scaffold, reasoning effort, token budget, shots, tools, sampling, sample count, language, quantization and hardware where relevant. Unknown configuration components are explicitly recorded as unknown; they do not become defaults.

One model can have many measurements of the same benchmark. SWE-bench Verified is not Pro. Pass@1 is not pass@k. Aider edits are not raw model completion accuracy. Arena Elo or Bradley-Terry estimates are cohort-dependent and are not percentages. Vision perception benchmarks do not establish image generation quality. GenEval, DPG-Bench, text rendering, editing fidelity and human preference each measure different dimensions. Provider claims, independent evaluations and local observations never share an unmarked provenance tier.

Raw run identity, typed known/unknown metadata, family-critical policy and comparison eligibility follow [benchmark comparability](benchmark-comparability.md). Calendar alignment is critical for preference/latency windows, not automatically for static accuracy. Raw unresolved evidence remains captureable. Score validation checks unit/range, metric direction, variant/config identity, table headers and exact numeric spans. Validate known constraints only; never reject a new benchmark because its score is not a percentage. Retractions append invalidation facts. Duplicate citations are not independent corroboration. Benchmark contamination and unsupported methodology lower evidence confidence but do not rewrite published values.

Derive strengths and weaknesses relative to a named task dimension, cohort and policy version. A demonstrated weakness requires an applicable poor measurement or direct documented limitation. “No score found” is a coverage gap. Catalog prose is displayed as publisher-claimed strength. Operational limits such as context, missing tools or expensive output are classified separately from empirical quality.

## Pricing evidence

Treat prices as decimal arithmetic with explicit currency and denominator. Vercel token prices must be interpreted using its documented unit; models.dev token costs are compared only after conversion. A missing price is unknown, not free. A zero price is accepted only when the source explicitly quotes zero.

A price quote references one provider offer and is scoped by underlying provider, region, service tier, token/context band, cache category, operation and image settings. Quote knowledge is `exact`, `proven_upper_bound` or `incomplete`; an upper bound requires cited component/range coverage and is invalid when any applicable component remains unknown. Conflicting active identity bindings prevent revision-based quality admission and inherited traits; offer-scoped proven facts remain usable only under explicit unknown-quality fallback. Preserve threshold boundary semantics. Distinguish cache read, cache write duration, uncached input, reasoning output and text/image token accounting. Image price may depend on resolution, quality, style, generated image count, input image tokens, inference steps or megapixels. Tool/search charges and peak/fast premiums remain separate components. Unknown components yield an incomplete estimate, not a misleading cheap candidate.

List-price cross-checks detect disagreements for the same offer and dimensions. They do not average different providers. Subscription or local marginal cost is a host billing regime, not a replacement for public list price; quotas, GPU memory and opportunity cost remain constraints. Under `varies_by_provider`, a quote needs a pinned provider or a defensible upper bound before strict budget admission.

## Freshness and publication

Freshness is independent for price, capability, identity, benchmark and observed latency. Proposed strict defaults: price at most 24 hours since successful confirmation, availability supplied by the live host, capability at most seven days and latency at most one hour. Historical benchmarks remain historical, but mutable-alias linkage needs current identity evidence. A `304` refreshes observation time without changing provenance bytes.

Every snapshot names schema version, policy/calibration version, source observations, per-field freshness, coverage, excluded facts and build hash. Adoption validates integrity/schema and labels aged facts; it need not reject an otherwise usable artifact because one offer has stale pricing. Every route independently checks fact ages against its strict requirements using the current clock. Last known good means integrity-valid, not perpetually fresh. Retaining an older generation never refreshes its facts or weakens strict admission. Manifest and sections are hashed. Publish by writing a complete temporary file, syncing it and atomically renaming the version pointer. Retain at least two verified versions and support rollback. Signing is required only for remote artifact distribution and remains an open trust-policy decision. Local ownership and file permissions still apply.

## Source rights and operating limits

Technical access is not redistribution permission. Track source license, terms URL, effective date, expiry and independent permissions for local research, extraction and redistribution, each `allowed`, `denied` or `unknown`. No permission implies another. Select the newest effective non-expired policy; same-time conflicts fail closed per [source access](source-access.md#precedence-and-conflict). Local snapshot compilation requires allowed research and extraction; distributable compilation/publication additionally requires allowed redistribution for every contributing source. Unknown/restricted evidence stays in the explicitly authorized local research artifact and is excluded from distributable bundles until approved. The committed local repository is not an approved public dataset release.

Collector reads only allowlisted source hosts. Revalidate every redirect and resolved address against private/link-local ranges; reject file URLs, arbitrary user URLs, decompression bombs and oversized bodies. Parsers and optional inference extraction get no filesystem authority or secrets. Source text cannot alter routing policy. Paid APIs and active evaluations require separate spend limits; the default research pipeline makes metadata GETs only.

## Verification before implementation is accepted

Exercise real conditional GET and both Retry-After formats; kill/restart during every stage; inject duplicate events, stale leases, source schema drift, partial outages and corrupted snapshots. Confirm last known good routing survives without weakening hard privacy/budget constraints. Check byte hashes, evidence locators, exact model coverage and the absence of benchmark inheritance. Replay identical observations twice and require identical snapshots. Test image input versus output, long-context bands, zero versus unknown prices and provider-varying quotes. Validate source rights exclusions and benchmark configuration comparability. Run end-to-end through the actual host's model registry and spawn path, not a synthetic ranked-list demo.

Open decisions: licensed aggregator access and budget; source refresh ceilings; anonymous model reveal policy; optional extraction model and spend cap; artifact distribution/signing; research raw-data publication rights; evaluation workload ownership. These do not require human intervention on every update, but they must be settled before their corresponding collectors are enabled.
